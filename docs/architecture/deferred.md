# Deferred decisions and boundary watch list

Review this file at every phase exit, and whenever a requirement touches one of these rows (§9.3 step 5).

The app runs only on the owner's machine, for the owner and a few friends (PRD scope revision; ADR 0014, 0016). Every row below is a local choice.

## Boundary watch list (§9.3)

Boundaries noted but not built, partial boundaries that may decay, and the friction to watch for.

| # | Boundary | State | Friction to watch for | Action when it appears |
|---|---|---|---|---|
| W1 | `rules` sits in the **Zone of Pain** (I=0, A=0, D=1.0, fan-in 23) | Accepted. It is stable and concrete, and calibration changes constants, not signatures (§4.7: only volatile components hurt there) | A calibration change forces edits in `use-cases`, `adapters` or tests beyond assertions, or the rubric changes shape (new components, per-segment weights) | Extract a `MatchingPolicy` interface in rules with the current rubric as one implementation chosen in Main. Record it as an ADR superseding part of 0002 |
| W2 | Adapters package splitting | Partial ("skip the last step" style folders with an enforced no-cross-import rule) | The first third-party dependency (database driver, model SDK, PDF library) that other adapter consumers do not need | Split that subfolder into its own package (`storage-sqlite`, `model-runtime-*`, `documents`) and add it to `components.mjs` |
| W3 | Use-case areas inside one package | Partial. Areas are folders with enforced isolation | An area wants its own release cadence, or a second builder works in parallel and conflicts | Promote that area to its own package (deployment-level, §5.6) |
| W4 | `TemplateNarrator` versus a model-written narration | Port in place; template today | Reasons read as generic (the "users distrust scores" risk) | Add a model narrator adapter; the verdict does not change |
| W5 | Background work as a process boundary | Request ports exist; in-process today; monitoring ticks in the same process | D4 trigger | A worker Main; a service never, unless the app stops being local |
| W6 | Tier 4 scraping as a process boundary | Package boundary only; off by default | A scraper crash takes down the process, or the scraping library needs another runtime (JobSpy is Python) | Run Tier 4 adapters in a child process behind the same `JobSource` port (a proxy adapter in-process, the real one outside) |
| W7 | Interview statefulness | `Interviewer.nextQuestion(profile, transcript)` is stateless | Latency or cost from resending the transcript, or a runtime that keeps sessions (Claude Code headless may) | Change the port shape with an ADR; the transcript stays owned by the use case |
| W8 | Spending guard and spend charge as cross-cutting concerns | `SpendingGuard` and `SpendAttribution.charge` called inside cost-incurring interactors (ADR 0010, 0015) | A new cost-incurring use case forgets either. For the charge, `unattributedSpendMicros()` above zero in a test or in the running-cost panel's "other" line without deleted profiles | Make both decorators applied in Main to every cost-incurring input port, and add an architecture check. `RunJobSearch` keeps its own charge because only it knows the run id |
| W9 | Results read model versus matching write model | Separate ports (`ResultsReadModel` versus `MatchRecords`) over one store | Results queries slow down, or need joins the write model resists | A dedicated read store (CQRS-style). No use-case change |
| W11 | "Apply shown" measured at `ListResults` | Decorator on `ListResults` only (ADR 0011) | P3-T12's streamed view renders Apply cards from `ResultsFeed` notices without a `ListResults` call, so the north star lags or misses profiles | Add a `ResultsShown` input port that the view calls when it renders cards, and wrap it with a decorator that emits the same `apply-verdict-shown` event |
| W14 | Shared posting enrichment charged to the first fetcher | Interpretation (D13) | Spend per profile is skewed for whichever friend searched first | Charge enrichment to a shared "catalog" bucket and show it as its own line on the running-cost panel. A ledger query change, not a port change |
| W15 | The local-request check is called by convention in the web Main | `acceptsLocalRequest` exists and is tested; the web Main does not exist yet | Any route handler added without the check, or the framework's own endpoints (dev server, static files, API routes) bypassing it | Put the check in the framework's single request hook (middleware) so it cannot be skipped per route, and add a web-level test that a foreign Host is refused on every route |
| W16 | Deleting a profile while its background work runs | `DeletePerson` erases stores; it does not wait for or cancel the person's queued search or re-score | A search for a deleted profile writes matches or spend after erasure | Give the work queue a cancel-by-person operation and have `DeletePerson` request it through a port it owns, before erasing |

Closed by the scope revision: W10 (model-runtime and data terms per market: there are no markets; the owner configures the model account so data is not used for training, Privacy 4), W12 (out-of-order billing events: no billing), W13 (money-based fair-use cap: built as the monthly budget, ADR 0015).
